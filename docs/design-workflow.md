# Design workflow

Code is the source of truth for tokens, and platform is the source of the code: `src/platform/styles/tokens.css` (colors, radii, shadow, widths) and `src/platform/styles/type.css` (the type scale) are platform's files byte for byte, mirrored with the rest of its web app, and `src/styles/tokens-demo.css` adds only what platform lacks. Together they decide what the app paints. Everything else is generated from them or follows them:

- `docs/design-spec.md` - the token tables, generated by `node scripts/design-spec.ts --write`
- The [grounded-design skill](../.agents/skills/grounded-design/SKILL.md) - how to use the tokens (one primary per view, the 4px grid, row heights, icon sizes, dense information)
- The Figma file [Grounded Design System](https://www.figma.com/design/Ehq3tczqsfQb0ElDb5xgeE/Grounded-Design-System?node-id=2059-203) - variables "Grounded Color" (Light and Dark modes) and "Grounded Scale" (radius, space, size), the `Grounded/*` text styles, the board, the Spec frame and the Examples on the Grounded page

## A token change

1. Take platform's `tokens.css` or `type.css` with `pnpm sync:platform` when platform changes them; put a demo-only token in `tokens-demo.css`
2. Run `node scripts/design-spec.ts --write`; without `--write` it fails while the spec is stale or the skill names a token that doesn't exist
3. Run `node scripts/figma-tokens.ts`. It prints the payload: every color with its Light and Dark hex, scopes and `var(--color-*)` code syntax, the radii, the 4px spacing steps the code uses and the page widths
4. Ask an agent with the Figma MCP to run the snippet below through `use_figma` on file `Ehq3tczqsfQb0ElDb5xgeE`, with the payload pasted in as `const payload = ...;`
5. The snippet returns `created`, `updated`, `unchanged` and `notInCode`. It never removes a variable; `notInCode` lists the ones Figma has and code lacks (today `radius/chip` and `radius/full`), so check where they're bound before anyone deletes one

Swatches and frames bound to the variables update on their own. The hex labels on the Tokens / Color frame and the Spec frame are text, so ask the agent to refresh them after a color changes.

```js
// const payload = <output of node scripts/figma-tokens.ts>;
const rgba = (hex) => {
  const [r, g, b, a = 255] = hex
    .slice(1)
    .match(/../g)
    .map((pair) => parseInt(pair, 16));
  return { r: r / 255, g: g / 255, b: b / 255, a: a / 255 };
};
const same = (x, y) => JSON.stringify(x) === JSON.stringify(y);
const collections = await figma.variables.getLocalVariableCollectionsAsync();
const local = await figma.variables.getLocalVariablesAsync();
const report = { created: [], updated: [], unchanged: 0, notInCode: [] };
async function sync(group, type, valuesFor) {
  const collection = collections.find((c) => c.name === group.collection);
  if (!collection) throw new Error(`No collection ${group.collection}`);
  const modes = Object.fromEntries(collection.modes.map((m) => [m.name, m.modeId]));
  const mine = local.filter((v) => v.variableCollectionId === collection.id);
  for (const token of group.variables) {
    let variable = mine.find((v) => v.name === token.name);
    const isNew = !variable;
    if (isNew) variable = figma.variables.createVariable(token.name, collection, type);
    let changed = false;
    for (const [mode, value] of Object.entries(valuesFor(token, collection))) {
      const modeId = modes[mode] ?? collection.modes[0].modeId;
      const current = variable.valuesByMode[modeId];
      const close =
        current && typeof value === "object"
          ? ["r", "g", "b", "a"].every((k) => Math.abs((current[k] ?? 1) - value[k]) < 0.002)
          : current === value;
      if (!close) {
        variable.setValueForMode(modeId, value);
        changed = true;
      }
    }
    if (!same([...variable.scopes].sort(), [...token.scopes].sort())) {
      variable.scopes = token.scopes;
      changed = true;
    }
    if (variable.codeSyntax.WEB !== token.web) {
      variable.setVariableCodeSyntax("WEB", token.web);
      changed = true;
    }
    if (isNew) report.created.push(token.name);
    else if (changed) report.updated.push(token.name);
    else report.unchanged += 1;
  }
  const names = new Set(group.variables.map((t) => t.name));
  report.notInCode.push(...mine.filter((v) => !names.has(v.name)).map((v) => v.name));
}
await sync(payload.color, "COLOR", (token) => ({
  Light: rgba(token.light),
  Dark: rgba(token.dark),
}));
await sync(payload.scale, "FLOAT", (token, collection) => ({
  [collection.modes[0].name]: token.value,
}));
return report;
```

## A design change in Figma

- The designer edits in Figma: a variable value, a component, a board frame or an Example
- An engineer moves the change into `tokens.css` or the kit in `src/ui`, then runs the token change steps above, so Figma gets the code's version back
- A variable someone changed only in Figma shows up under `updated` on the next sync, which overwrites it; that list is the drift report, so move a change into code first if it should stay
- `node scripts/design-spec.ts` catches the spec or the skill drifting from the stylesheets

## Code Connect

Code Connect needs a published library on an Organization or Enterprise plan, and this file's team doesn't have one, so `add_code_connect_map` and `send_code_connect_mappings` refuse it. Until then each core component's description ends with a `Code:` line (for example "Code: Button in src/ui/button.tsx"), which Dev Mode and the MCP show beside the component. Those lines are the mapping list to send once the plan allows it.

- Mapped by description: Button, Icon button, Menu button (a Button with a trailing chevron), Tag, Count, Chip, Kbd, Tab, Segment, Tooltip, Menu item, Input, Select, Search field, Step mark, Fact, the Pebble and Grounded marks, and the kit's Confirmation dialog
- No Figma component yet: a table row (`Table`), `EmptyState`, `DialogContent` on its own

## Specs

Figma's Specs (Markdown design-language docs, open beta since Oct 14) aren't reachable from the Plugin API or the MCP. The Spec frame beside the board on the Grounded page carries the key sections instead: colors as swatches bound to the variables in both modes, the type scale, radius and spacing bound to Grounded Scale, and the usage rules. To make a Figma Spec, paste `docs/design-spec.md` and the Tokens, Layout and Dense information sections of the grounded-design skill into one by hand.

## Examples

The Examples rows on the Grounded page are captures of the running app at 1440 by 900, light above dark. New captures go beside the old ones with the date in the name, so earlier frames stay for comparison.

## Code layers

Figma's code layers (open beta) run a small HTML and JS project on the canvas. Use one for an interaction that a static frame can't show (the sliding segment box, Flow's staircase, the Pebble dock moving sides): build a standalone page, import it with the MCP's `send_code_to_figma` onto the Grounded page, and keep the real behavior in `src`. The kit itself stays as Figma components.
